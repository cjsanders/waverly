---
title: Local development
description: Doppler-backed bun run dev for website, affiliate, and docs.
---

Normal `bun run dev` loads each app's selected Doppler config. Install the [Doppler CLI](https://docs.doppler.com/docs/cli) first.

## One-time setup

```sh
bun install
doppler login
(cd apps/affiliate && doppler setup --no-interactive)
(cd apps/website && doppler setup --no-interactive)
(cd apps/docs && doppler setup --no-interactive)
```

Login and setup are per machine and checkout. Each app's `doppler.yaml` selects that project's `dev` config (`waverly-affiliate`, `waverly-website`, `waverly-docs`).

## Start the apps

```sh
bun run dev
```

Root `bun run dev` starts the three web apps through Turbo. Each app's `dev` script already runs `doppler run`, so every app loads only its own project after Turbo starts that task. **Do not** wrap the root command in a single `doppler run`.

In a second terminal, sync/watch the affiliate Convex development deployment (also Doppler-backed):

```sh
bun run --cwd apps/affiliate dev:convex
```

The root command does not start that watcher.

| App       | URL                                   |
| --------- | ------------------------------------- |
| affiliate | `https://affiliate.waverly.localhost` |
| website   | `https://website.waverly.localhost`   |
| docs      | `https://docs.waverly.localhost`      |

Portless assigns ports through `PORT`. The WorkOS development callback in Doppler is `https://affiliate.waverly.localhost/api/auth/callback` — register it and `/api/auth/sign-in` in the WorkOS development environment. See [WorkOS setup](/workos).

## Secrets

Keep Convex (`VITE_CONVEX_URL`, `VITE_CONVEX_SITE_URL`, `CONVEX_DEPLOYMENT`) and WorkOS values in the affiliate development Doppler config.

Existing `.env.local` files can still hold optional local-only values such as `TEST_USER_EMAIL` / `TEST_USER_PASSWORD`. Doppler wins when the same key is in both. Do not use `.dev.vars` for Doppler-backed affiliate development: Cloudflare loads those instead of process-environment secrets. Restart the dev process after changing Doppler values.

For personal overrides, run `doppler setup --config dev_personal` inside the app directory. No script edit is needed.
