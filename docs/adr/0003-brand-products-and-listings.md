# Brands own a Product catalog; a Listing is one buyable item on one Marketplace

Product data moves out of `offers.metadata` into a brand-owned product table (`brandProducts`) scoped to the brand's tenant, and a `listings` table records each place a product is sold. A Listing is the buyable item on a marketplace (a child ASIN, a Walmart item id, a Shopify variant), unique per tenant on `marketplaceId` + `externalId`, with an optional `parentExternalId` for variant grouping; one product may therefore have several listings on the same marketplace. Listings are entered by brands in the app for now, but every row carries `externalId`, `url`, `source`, and optional `lastSyncedAt` and `snapshot` fields so a later Amazon or Walmart import can upsert into the same rows without a schema change. Products reference only their tenant, not an `advertiserId`; advertisers remain an operator-side concept for programs and conversions until the cross-tenant model in [0006](0006-listings-are-brand-tenant-scoped.md) is designed. The table is named `brandProducts` rather than `products` because preview deployments seeded before this change hold rows in a legacy `products` placeholder table; Convex validates every declared table's existing rows when a schema is pushed, so reusing the name would block deploys to reused previews, whereas an undeclared table is ignored and expires with the preview.
